# 论文证据人工审核工作流 PRD

> 状态：评审稿（2026-08-07）

## 1. 背景与目标

当前“论文证据”已支持检索、AI 截取段落、自动挂接与置信度更新，但缺少人工把关。目标：把“AI 截取 → 人工审核 → 入库”变成**逐条处理**的工作流，入口与字段补全一致（表格工具栏按钮），弹窗在数据中心内一条一条处理（连接、连接功能等对象）。

## 2. 用户流程

```text
数据中心 → Mirror KG / Macro Clinical → 选择“论文佐证审核”入口
  → 弹窗：选择对象类型 + 范围（低置信/全部/未锚定）
  → 加载待处理队列（一条一条）
  → 每条：
      检索论文（自动，多篇候选）
      选一篇 → AI 截取段落（方向/段落/理由/置信度）
      [翻译] 段落译成中文（可编辑）
      人工审核：修改段落/方向/置信度
      [入库] → 写 mirror_evidence_records + 更新对象 evidence_text + 置信度
  → 下一条 / 跳过 / 完成进度
```

## 3. 功能点

1. **入口**：字段补全同款（表格工具栏按钮），数据中心下方出现处理弹窗；
2. **队列加载**：目标类型（连接/投影功能/回路功能/回路步骤等）+ 范围（低置信 <0.5 / 全部 / 未锚定）；
3. **逐条处理**：一次展示一个对象（名称/ID/当前置信度）；
4. **检索+截取**：调用现有 search/extract；多条候选可选；
5. **翻译按钮**：段落 → 中文，人工可编辑（中英对照显示）；
6. **人工审核**：段落、方向、推荐置信度均可修改；显示 AI 推荐值；
7. **入库**：attach（paper_verification，自动更新置信度，上限 0.85）；
8. **进度**：已完成/跳过/失败计数，逐条可回退（上一条）；
9. **明细**：每条处理结果可见（evidence_id/PMID/方向/置信度）。

## 4. 交互设计

- 弹窗固定在数据中心下方（bottom panel，类似多目标字段补全），高度约 60vh，左侧对象信息，右侧论文与截取区；
- 按钮：检索论文 / AI 截取 / 翻译 / 入库 / 跳过 / 上一条 / 下一条；
- 状态色：pending 灰、done 绿、failed 红、skipped 黄。

## 5. 数据流与接口

复用现有：
- `POST /api/ontology/evidence/search`
- `POST /api/ontology/evidence/extract`
- `POST /api/ontology/evidence/attach`

新增：
- `GET /api/ontology/evidence/queue?target_type=&scope=&limit=`：返回待处理对象队列（id + 名称）；
- `POST /api/ontology/evidence/translate {text}`：DeepSeek 译成中文，返回译文（reviewer 权限）。

## 6. 验收标准

- 入口从数据中心表格工具栏可打开；
- 弹窗逐条处理，可上一条/下一条/跳过；
- AI 截取后点翻译能出中文，可编辑；
- 人工确认后入库，数据中心该对象置信度更新；
- 进度计数准确，失败不中断队列。

## 7. 非目标（本期不做）

- 批量无人审核全自动挂接（仍保留在批量任务里）；
- 双模型交叉验证；
- OA 全文段落定位（本期摘要优先）。
