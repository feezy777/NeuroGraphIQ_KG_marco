# 01_cover

本次汇报介绍 NeuroGraphIQ KG V3 的多粒度脑区知识图谱构建方法。我们面对的不是一个普通的数据导入问题，而是一个同时涉及神经科学语义、异构资源整合、大语言模型不确定性和知识责任边界的系统工程。整个方案最重要的设计立场，是不让模型直接决定知识真伪，而是把模型放入可校验、可审核、可追溯的治理流程。接下来我会依次说明问题规模、七层知识体系、全局与局部构建架构、Mirror 治理、正式知识晋升和最终成果。希望大家在听完后能够回答三个问题：知识从哪里来，为什么可以相信，以及出现争议时如何追溯和纠正。

---

# 02_problem_scale

首先看为什么需要建设这套系统。脑图谱资源来自不同机构和不同历史阶段，既有 XML、Excel、CSV 和 OWL 等格式差异，也有命名体系、空间粒度和关系语义的不一致。即使模型能够从文本或表格中抽取关系，如果没有明确的粒度边界和写入边界，一个局部错误也可能沿着回路、功能和映射关系扩散。项目规模说明我们解决的不是单点算法：当前包含四十二条后端路由、八十八个服务、十四个前端页面、五层 Schema、五十九次数据迁移和一千一百七十三个测试函数。系统因此采用候选、规则校验、模型提取、Mirror、人工审核和 Final 的分层漏斗。评委如果关注这些数字是否代表复杂度堆叠，关键判断是每一层都对应独立责任，而不是重复实现。

---

# 03_knowledge_layers

在明确问题之后，我们先建立七层知识体系，避免后续工程围绕数据库表而不是科学语义展开。最底层是脑区实体，向上依次是连接、回路、功能、证据、三元组和映射。连接回答两个脑区之间是否存在结构或投射关系，回路强调多个节点和步骤构成的有序机制，功能描述脑区或回路承担的作用，证据层保存这些判断的来源。三元组层提供统一查询表达，映射层只负责跨图谱和跨粒度的显式对应。这里最重要的原则是同粒度内构建、跨粒度显式映射。名称相似并不等于解剖等价，空间重叠也不等于完全匹配。如果评委追问为什么不把所有脑区放在一个大图里，答案是统一查询可以建立在隔离存储之上，而语义混合一旦发生就很难可靠恢复。

---

# 04_global_architecture

这一页给出全局构建架构。左侧从资源登记开始，每个图谱先形成带版本、校验和和来源信息的资源记录，再以 Import Batch 追踪一次具体导入。解析结果不是直接知识，而是候选对象；候选先经过确定性规则，再由受控的模型能力提取连接、功能、回路和投射等信息。所有模型输出首先进入 Mirror KG，随后完成去重、双模型复核、结构交叉验证和专家终审，最后才通过 Promotion 写入 Final KG。右侧是图谱探索、症状查询、数据中心和离线导出等消费端。这个架构的核心是写入边界：模型不得直接写 Final，也不得自动审核或自动晋升。如果评委问 Mirror 是否增加了不必要的延迟，需要权衡的是知识错误的不可逆成本；对于正式科研知识，受控延迟优于快速污染。

---

# 05_import_pipeline

下面进入局部构建流程，先看数据导入。AAL3 使用 XML，包含一百六十六个 ROI；Macro96 使用 Excel，包含九十六个脑区。两类资源保留独立解析器，因为它们的字段结构、层级关系和标识生成方式不同，但它们共享统一的资源登记、Import Batch 和 Candidate Pool 语义。资源登记解决“导入的究竟是哪一版数据”，批次记录解决“这次操作处理了哪些记录、成功与失败多少”，专属解析器负责格式差异，候选池则把结果变成后续规则和模型都能理解的统一对象。幂等设计保证重复执行不会产生重复知识，唯一索引约束候选身份，溯源字段保留原始文件和记录位置。评委如果关注新增图谱的接入成本，主要工作集中在解析适配器，而治理和审核链可以复用。

---

# 06_quality_rules

候选生成后，系统不会立即调用大模型，而是先运行十二条确定性规则。规则覆盖必填字段和数据类型、语义标识、唯一性、拓扑、自环与孤立节点、关系端点、资源与批次溯源，以及证据完整性。这样做有两个好处：第一，明确的错误不需要消耗模型调用；第二，规则结果可以重复执行和精确解释。质量评分由完整性百分之三十、溯源百分之二十、拓扑百分之二十、证据百分之二十和关联百分之十组成，达到八十分才进入下一阶段。低分数据先进入 Tier 1 确定性修复，无法确定的问题再进入 Tier 2，由 DeepSeek 给出建议，但建议必须由人工批准或拒绝。若评委质疑权重是否具有普适性，需要强调权重是可配置治理策略，而规则事实本身保持稳定。

---

# 07_llm_capabilities

通过统一的 Provider 抽象层，系统可以在 DeepSeek 和 Kimi 之间复用相同的任务接口、运行记录和错误处理。七类能力包括连接提取、脑区功能、回路、投射功能、回路功能、回路步骤和三元组整合，其中三元组整合是确定性过程，不依赖模型再次生成。模型能力都受到两个边界约束。第一，同粒度内提取，不能因为名称接近就跨 atlas 或跨粒度连接；第二，跨粒度关系必须查询显式 Mapping 表。API Key 只保存在后端，前端只提交任务参数，所有原始响应、模型版本和 Prompt 都被记录。评委如果问双模型是否意味着简单投票，答案是否定的：模型首先独立工作，后续盲审比较的是证据和结构结论，而不是把两个概率输出机械平均。

---

# 08_mirror_write

模型任务采用 Pack 化编排，而不是一次提交全部候选。默认每个 Pack 处理二十对对象，Dry Run 会预估 Pack 数、Token 和费用，使研究人员在执行前了解成本。运行过程支持 Skip Existing、暂停、取消和恢复，因此网络失败或供应商限流不会迫使整批任务重来。四步复合流程先提取连接和功能，再提取回路与步骤，然后提取投射，最后由确定性逻辑整合三元组。模型运行记录保存在 llm_extraction_runs，逐项结果和 raw response 保存在 llm_extraction_items，随后由 llm_to_mirror 完成结构转换并写入八张 Mirror 表。这里的关键不是表数量，而是概率生成与确定性写入分离。评委如果关注可复现性，我们可以从运行记录恢复当时模型、Prompt、输入和原始输出。

---

# 09_mirror_governance

进入 Mirror KG 后，数据仍然只是待治理知识。第一项机制是 Canonical Key 去重：系统在写入时生成规范键，对重复候选保留高置信度结果，同时保留双方溯源；已经审核、已经晋升、跨 atlas 或跨粒度的数据永不自动合并。第二项机制是 DeepSeek 与 Kimi 的双模型盲审。两者都基于同一证据独立复核，形成 consensus 时可以加速人工审核，形成 conflict 时必须升级专家处理。第三项机制是结构交叉验证，从回路到步骤再到投射检查完整性，也从投射反向查找对应回路，发现端点、顺序和跨表引用问题。如果评委问为何不能直接依赖数据库唯一约束，唯一约束只能发现键冲突，不能判断科学语义是否一致。

---

# 10_validation_gates

正式晋升前必须连续通过三道闸门。第一道是规则闸门，十二条规则把问题分为 Blocker 和 Warning；Blocker 必须修复，Warning 可以带标记进入后续复核。第二道是模型闸门，双模型盲审形成共识或冲突，共识代表证据与结构判断一致，但仍不等于自动批准；冲突则直接升级。第三道是专家闸门，领域专家可以 approve、reject 或 request changes，并留下审核意见。三道闸门分别优化效率、独立复核和知识责任，任何单点通过都不能替代完整链路。如果评委关注人工审核是否成为瓶颈，系统通过规则拦截、共识排序和批量界面减少低价值操作，把专家时间集中在真正冲突和高风险的知识上。

---

# 11_final_kg

只有全部闸门通过后，记录才进入 Promotion。Promotion 不是一个普通的复制按钮，而是先预览 Mirror 到 Final 的映射结果，再要求强确认，执行时同时写入八张 Final 表和审计记录。Final KG 的实体包括 BrainRegion、Function、Circuit、Step 和 Projection，关系使用十二种标准谓词，统一查询面由 final_kg_triples 提供。底层按照 macro、meso、sub、fine 和 molecular 五层 Schema 隔离，不同粒度可以在查询层联合，但不能在存储语义上自动混合。跨粒度只允许 exact match、part of 和 overlaps 三类显式关系。评委如果问 Schema 隔离是否影响性能，这里优先保护语义正确性，查询优化可以通过视图和图数据库同步完成。

---

# 12_traceability

知识进入消费端之后，系统仍然能够解释每一个事实的来历。反向溯源共有八个清晰阶段：从 Final fact 找到对应 Promotion，再找到专家 Review 和规则或模型 Validation；继续向前可以定位具体 Extraction item、所属 Run、输入 Candidate，最后回到 Import Batch 和原始 Resource。Run 与 Candidate 必须分开，因为前者记录某次模型执行的环境、Prompt 和供应商信息，后者记录进入执行前的结构化输入；Import 与 Resource 也承担批次操作和静态来源两种不同责任。这条链同时保留原始响应、模型版本、Prompt、批次和资源定位。评委如果给出一个有争议的三元组，我们可以逐级展示它如何被产生、复核、批准，并确定应在哪一层修正。

---

# 13_innovations

回顾整个方案，六项创新并不是彼此独立的功能清单，而是一套互相补位的可信机制。分层漏斗把不同责任拆开；Mirror KG 和 Canonical Key 提供安全中转与受控去重；双模型盲审避免单模型自证；Tier 1 与 Tier 2 把确定性修复和概率建议分离；八步溯源使每个正式事实都可追责；五层 Schema 和显式 Mapping 保护多粒度语义。它们共同把大语言模型从“知识裁判”降级为“受控提取工具”。如果评委要求用一句话概括创新，答案是：可信知识不是模型偶然答对，而是错误可发现、决策可追责、结果可回溯，并且纠正能够落到明确的责任层。

---

# 14_results_roadmap

目前系统已经形成端到端闭环。能力侧实现了七类提取、十二条规则、两级增强、双模型盲审、结构交叉验证、Promotion 和三元组整合；工程侧形成十四页工作台、四十二条路由、八十八个服务、五十九次迁移和一千一百七十三个测试函数。这些结果证明治理架构已经可以运行，而不是停留在概念图。下一阶段有四个方向：接入更多粒度与更多 atlas，推进 Final KG 与图数据库同步，提高跨粒度映射的自动候选生成能力，并增强 Graph Explorer 的查询与解释功能。需要特别说明，自动化扩展只发生在候选和辅助判断阶段，写入边界、审核责任和溯源要求不会因为规模增长而放松。

---

# 15_qa

以上是 NeuroGraphIQ KG V3 的多粒度脑区知识图谱构建方法。我们从异构资源出发，通过七层知识体系定义语义边界，再用候选、规则、模型、Mirror、三道闸门和 Promotion 构成治理闭环，最终把知识交付给可查询、可导出、可追溯的 Final KG。整套方案希望解决的核心问题，是在利用大语言模型规模能力的同时，不把知识责任交给模型。欢迎大家围绕数据治理、双模型复核、专家审核、八步溯源和跨粒度 Mapping 继续交流，谢谢。
